# DSS-HIR — The Platform-Absorption Tier — Reserved Sub-Plan (09.5)

> **Reserved scope.** Owns **DSS-HIR**: an optional tier *above* [HIR](./09-hir-plan%20-%20ok.md) that any source language may opt into, carrying two independent facets:
>
> 1. **The DSS Native Runtime** — threads, async, filesystem, sockets, timers, synchronization, workers, gui — which **absorbs platform discrepancies** so a language that opts in gets one behaviour on every target.
> 2. **The ownership & reclamation analysis** — the T0–T4 mechanism lattice and the C0–C3 cycle lattice that replace garbage collection outright. **No GC, no cycle collector, no deferred reclamation, ever.**
>
> **Why 09.5 and not inside [`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md).** Both facets are **language-agnostic**. Ownership, escape and borrow are properties of the **value graph**, not of surface syntax — so the analysis belongs where the value graph is. Filing a universal tier inside one language's plan is exactly the per-language engine work [`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §4.6 forbids. DSS Axis is DSS-HIR's **first consumer**, not its owner.
>
> **The pipeline:** `AST → [DSS-HIR, if any facet is enabled] → HIR → MIR → LIR → …`
>
> **Numbered 09.5** for the same reason 08.5 and 12.5 are: it is a tier that sits between two existing numbered plans and belongs adjacent to the one it lowers into.

## 1. Trigger

**Two independent triggers**, matching the two facets.

### 1.1 Reclamation half — early, and buildable against today's engine

Opens when a language declares a reclamation lattice (§4.3). ★ **The first deliverable is not a feature — it is a proof of harmlessness** (§4.4): the tier must be a **provable no-op for c-subset**, with every C example emitting **byte-identical** code whether the tier is present or absent. That pin is buildable **now**, needs no new language, and is the agnosticism test for the whole design. If it cannot be made green, the tier is in the wrong place.

### 1.2 Runtime-services half — behind a consumer

Opens when a shipped language declares `runtime.enable = true` **and** at least one service has a named consumer. Services open **individually**, not as a block (the [`plan-21`](./21-runtime-reserved-plan%20-%20tbd.md) §1 module-by-module discipline).

## 2. The two-tier thesis

### 2.1 HIR is the C/C++-expressible floor

**HIR's semantic ceiling is what C/C++ and their ABIs can express.** That is not a limitation — it is what makes HIR a *stable* pivot: every construct in it has a known lowering to native code and a known spelling in a language [`plan-10`](./10-source-translation-plan%20-%20tbd.md) can transpile to. Anything richer than C/C++ semantics does not belong in HIR; it belongs above it, and must **desugar into** it.

⚠ **This sharpens [`plan-09`](./09-hir-plan%20-%20ok.md)'s framing rather than contradicting it, and the difference must be stated rather than absorbed.** Plan 09 defines HIR as *"language-neutral, structured, fully typed … the layer where transpilation, native lowering, GPU lowering, and WASM lowering all converge."* That is unchanged. What 09.5 adds is a **ceiling**: neutral *and* bounded by C/C++ expressibility. → §8 Q2.

### 2.2 DSS-HIR is where the platform stops mattering

DSS-HIR carries constructs that are **higher than C** and **absorb platform difference**: a socket, a thread, a timer, a UI surface. Each lowers to HIR **for a specific target**, choosing the platform vehicle there. The consuming language never sees the difference — that is the entire product claim.

```
AST
 │
 ├─(any DSS-HIR facet enabled)──►  DSS-HIR
 │                                   ├── reclamation analysis  (§4)  ─ compile-time only
 │                                   └── runtime services      (§5)  ─ threads · async · filesystem
 │                                                                     sockets · timers · synchronization
 │                                                                     workers · gui
 │                                          │ target-parameterised lowering
 ▼                                          ▼
HIR  ◄──────────────────────────────────────┘        the C/C++-expressible floor
 │
MIR ─► LIR ─► object formats                          (unchanged, as today)
```

### 2.3 ★ The disabled path must be COMPLETE, not degraded

The single most important lock in this plan. A language that declares **no** DSS-HIR facet must reach HIR by a path that is **first-class, not a fallback**.

If DSS-HIR ever becomes the *only* way to express async, or threads, or ownership, then every language that brings its own model — C++ coroutines, Rust futures, Go goroutines, JS promises, C# tasks — is forced through DSS's runtime, and "the universal engine" has quietly become "the engine that runs DSS's runtime." That is a thesis-falsification event, not a design detail.

**Consequences that must hold:**

- HIR keeps its own attribute families for async / exceptions / effects ([`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §4.2's lock, preserved verbatim) so a foreign model lowers through plain HIR.
- c-subset compiles today and must continue to compile **byte-identically** (§4.4).
- No engine code may assume a DSS-HIR node exists.

→ `D-DSSHIR-DISABLED-PATH-COMPLETE`.

### 2.4 ⚠ The two facets are independent — and that is what makes freestanding work

The proposed config spells two blocks, and their independence is **load-bearing**, not incidental:

```jsonc
"memory":  { /* the reclamation lattice — a compile-time PASS, no runtime service */ },
"runtime": { "enable": true /* the platform services — real code linked in */ }
```

★ **This is precisely what [`plan-28`](./28-driver-builder-plan.md) needs.** A kernel driver or a boot image wants **full ownership analysis** (it is compile-time and costs nothing at runtime) with **zero runtime services**. `memory` on + `runtime.enable` off *is* the freestanding profile that plan 28 §9.1 asked the engine to keep reachable — realized by an existing config switch instead of a mechanism invented later.

⚠ **A stated correction to the proposed pipeline, offered rather than silently applied.** The sketch gates DSS-HIR on `enableRuntime` alone: `AST → [if enableRuntime = true: dss-hir] → HIR`. But the reclamation analysis also lives in DSS-HIR and must be available when `runtime.enable` is **false** — otherwise the freestanding cell above loses ownership analysis, which is the one thing it most wants. **Recommendation: the tier is entered when _any_ facet is enabled**, not when `runtime.enable` specifically is. → §8 Q3.

## 3. The runtime services

| Service | Absorbs | Lowering vehicles (**DOCUMENTED**) |
|---|---|---|
| **threads** | thread creation, join, TLS, affinity | pthreads · Win32 · `wasi-threads` / none |
| **async** | the scheduler, `Task`-shaped awaitables, cancellation | one scheduler over the thread service; stackless state machines |
| **filesystem** | paths, case rules, permissions, atomic replace, watching | POSIX · Win32 · sandboxed mobile · virtual FS |
| **sockets** | TCP/UDP/TLS, name resolution, readiness | BSD sockets · Winsock · platform TLS |
| **timers** | monotonic clocks, deadlines, wall-clock vs steady | `clock_gettime` · QPC · `mach_absolute_time` |
| **synchronization** | mutex, rwlock, semaphore, barrier, latch, condvar, once | primitives from [`plan-21`](./21-runtime-reserved-plan%20-%20tbd.md) §2.4 |
| **workers** | ★ job execution **where OS threads are unavailable or restricted** | OS threads · Web Workers (WASM) · mobile background-execution APIs · a manual job queue |
| **gui** | window, surface, input, IME, insets, event loop | **realized by [`plan-27`](./27-gui-plan.md)** — Layer 1 shells + Layer 2 renderer |

★ **`workers` is the service that proves the thesis.** Every other service has *some* native analogue everywhere. Workers do not: WASM has no threads without SharedArrayBuffer + COOP/COEP headers, and mobile platforms restrict background execution by policy, not capability. A tier that can present one worker abstraction over "real OS threads" **and** "a cooperative job queue because the platform forbids threads" is absorbing a genuine discrepancy rather than renaming a uniform one. → `D-DSSHIR-WORKERS-NO-THREAD-FALLBACK`.

⚠ **Two services already have owners and must not be re-designed here.** `gui` is [`plan-27`](./27-gui-plan.md)'s; `synchronization`'s low-level primitives are [`plan-21`](./21-runtime-reserved-plan%20-%20tbd.md) §2.4's. DSS-HIR owns the **interface and the selection**, never the implementation. → `D-DSSHIR-SERVICE-OWNERSHIP-SPLIT`.

⚠ **`workers` overlaps [`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §3.7's "base service"** (one up/down/recover lifecycle across Windows Service, systemd, launchd, Android background service). One of the two owns it. → §8 Q5.

## 4. Reclamation — the lattices that replace garbage collection

> **The commitment, stated once and without hedging: no GC, no cycle collector, no deferred reclamation, no finalizer queue, no background collection — ever.** Reclamation happens at program points the compiler chose and can name.
>
> ⚠ **REVISED 2026-09-04 (operator ruling, [`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §2.3b).** This section used to continue: *"Where it cannot prove a program safe, it **refuses at compile time** rather than leaking at run time."* **That is reversed.** Failure to prove a **lifetime, aliasing, mutation, escape or thread-boundary** property now **materializes deterministic runtime enforcement** (the **TD** tier, §4.2a) instead of rejecting the program. **Acyclicity is the one exception and stays a static refusal** (§4.3, C4) — a non-tracing mechanism cannot reclaim a cycle, and that is the whole reason the exception exists. The prior text is quoted rather than deleted because the replacement is only legible against it.

### 4.1 The trilemma, stated before it is resolved

You cannot have all three:

**(i)** accept every program · **(ii)** no runtime GC or cycle collector · **(iii)** no leaks

**DOCUMENTED — what everyone else gave up:**

| System | Picks | Gives up |
|---|---|---|
| **Rust** | (ii) + (iii*) | (i) — annotated lifetimes, programs rejected. ★ And (iii) is qualified: `Rc` **cycles leak**, and Rust explicitly declares leaking *safe*. |
| **Koka (Perceus), Lean 4 (FBIP)** | (i) + (ii) | (iii) — sound **only because their data is inductive and acyclic by construction**. That is the precondition, not a footnote. |
| **Swift ARC** | (i) + (ii) | (iii) — leaks without `weak`/`unowned` annotations. |
| **C++ `shared_ptr`** | (i) + (ii) | (iii) — cycles leak. |

★ **Nobody solves cycles automatically without a collector.**

⚠ **RESOLVED TWICE, and the second answer is the live one.**

*The 2026-08-12 answer, kept because the current one is only legible against it:* given "no GC at all", the design took **(ii) + (iii)** and gave up **total (i)** — it **refused** the residual it could not prove, with an explicit visible escape hatch (`@manual`, §4.8).

**The 2026-09-04 answer** keeps **(ii)** and **(iii)** and recovers **(i) except for the type-level cycle refusal**, by adding a term the trilemma never contained: **deterministic dynamic enforcement that is neither a collector nor deferred** (§4.2a). The escape hatch is deleted outright ([`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §2.3a).

★ **Why the reversal, stated as a cost rather than a preference.** A refusal tells a programmer that a **valid** program is inexpressible *because this year's analysis is not strong enough*. That makes the accepted set of the language a function of inference quality — it moves under everyone's feet as the analysis improves, and a programmer meets the frontier as a wall with no way through. Under the new answer they meet a **cost that appears in the tier artifact and shrinks as the analysis improves** (§4.5), never an impossibility. **The accepted set stops depending on the strength of the compiler's proofs**, and that is worth more than the purity of the refusal.

⇒ the divergence from Rust, Swift and Koka is now **wider**, not narrower: the cycle guarantee that was already strictly stronger than all three is unchanged, and the case each of them answers with a programmer-selected mechanism (`unsafe`, `Rc`/`RefCell`, `weak`/`unowned`, `shared_ptr`) is answered here by **lowering the semantics the programmer already wrote**.

### 4.2 The mechanism lattice — strict precedence, strongest provable tier wins

Every allocation site is classified by the **first tier that can be proven**.

| Tier | Mechanism | Cost |
|---|---|---|
| **T0** | **stack / scope-bound** — escape analysis proves it never outlives its frame; no heap | zero |
| **T1** | **unique ownership + move** — proven single owner, freed at last use (Rust's `Box`+move, with **inference** instead of annotations) | zero |
| **T2** | **borrow** — proven non-owning reference that cannot outlive its owner | zero |
| **T3** | **region / arena** — a group with a common inferred lifetime, freed as a unit | near-zero |
| **T4** | **compile-time refcount** — residual only, where aliasing is genuinely dynamic **and** the owning type graph is proven acyclic; Perceus-style **precise, non-deferred** RC, heavily elided | small, residual |
| **TD** | ★ **dynamic ownership record** — ⚠ **beside T4, not after it.** Where a property is real but unprovable — characteristically an object crossing concurrent execution boundaries — the record carries it: participants, readers, writers, thread participation, synchronization state, destruction state, lifetime state, allocation metadata. **Materialized automatically; never selected by the programmer.** §4.2a | the residual, per site |
| **T5** | ★ **does not exist** — no GC, no cycle collector, no deferred reclamation, no finalizer queue, no background collection. | — |

★ **T5's absence is a declared and tested property, not merely an unimplemented one.** → `D-DSSHIR-NO-T5-TIER`.

⚠ **T4 and TD are the SAME axis at different widths, and the distinction is load-bearing.** T4 is the *single-context* dynamic residual — a precise, elided, non-deferred count. TD is the *multi-context* one — a record, because a count cannot express who may read, who may write, or which contexts are still participating. Neither is a step toward T5: **TD is off the T-axis, not further along it.** The T-axis asks *how cheaply can this be proven*; TD is what happens when the answer is *it cannot be*, and it is why the lettered name is deliberate.

### 4.2a ★ The TD tier — deterministic enforcement, and why it is not a collector

The claim *"that is GC with extra steps"* is the obvious objection and is answered by property, not assertion. Five hold, and **a collector fails every one** (the full argument, with the language-side contract, is [`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §2.3):

1. **No traversal** — nothing walks the heap; no runtime type maps, no root sets, no mark phase. ★ This is §4.3's own decisive argument against a cycle collector, applied to TD unchanged.
2. **No deferral** — reclamation is the last participant releasing, a program point in the emitted code.
3. **No background thread, no safepoints, no stop-the-world.**
4. **Materialized per SITE, not per PROGRAM** — a program with an empty residual links none of it, and that is a number in the tier artifact (§4.5).
5. **Removed by PROOF, not tuned by knobs** — a better analysis *deletes* it.

⚠ **TD requires atomics and a declared storage provider.** Atomics are ISA-level ([`plan-21`](./21-runtime-reserved-plan%20-%20tbd.md) §2.4) and available freestanding; storage is not automatic. **A lattice that omits TD declares dynamic enforcement unavailable on that target — and there, and only there, an unprovable residual is a build refusal naming the missing provider.** That is the GPU body and the pre-allocator boot image ([`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §3.1a, §3.6a), and it keeps the two facets independently switchable (lock 3).

⚠ **The representation is THIS TIER's, not the language's** — no consuming language may depend on its shape, and no language surface may expose it. → `D-DSSHIR-DYNAMIC-OWNERSHIP-RECORD`.

★ **T2 is where the most work goes.** A **borrowed parameter needs no dup/drop at all** — the single largest refcount-traffic win in every published Perceus result (**DOCUMENTED**). Techniques named explicitly because each is separately measurable: **reuse analysis / FBIP** (when RC==1 at a destructuring point, reuse the cell in place — this is what makes Koka/Lean competitive with mutation, and without it T4 is just ARC), **drop specialization**, **dup/drop pair cancellation**, the **borrowed-parameter calling convention**, **escape analysis** (T0), **region inference** (T3), and **uniqueness/linearity inference** feeding T1.

### 4.3 The cycle lattice — decided at the TYPE level, before any value exists

★ **The decisive move.** Every conventional answer decides cycles at the *value* level — at runtime, by programmer discipline, by convention, or after the fact. It is decidable **statically**:

> A heap cycle **requires** a cycle in the **owning-edge type graph**. Compute the SCCs of the type graph restricted to owning edges. That is the whole analysis.

| Tier | Condition | Cost |
|---|---|---|
| **C0** | **proven acyclic** — the owning-edge graph has no SCC. No cycle can *ever* form. | zero cost, **zero annotation** — the overwhelming majority of real code, requiring no programmer action, which is what "100% automatic" has to mean |
| **C1** | **arena / region-owned** — the whole SCC lives in a region freed as a unit, so no refcount governs its members and cycles *inside* it are free | ★ the **primary** structural answer. This is why [`plan-27`](./27-gui-plan.md) §8's arena-per-window already works. ★ **Membership must be inferable, not only declared** — where region inference proves a set of values share a lifetime, arena them automatically; otherwise the canonical cases still cost programmer action and the model is conventional, not automatic. ★★ **The declared half is §4.3a, added 2026-09-04** — an owner names the region, and the declaration is CHECKED in both directions |
| **C2** | **non-owning back-edge** — the edge closing the SCC is proven a borrow. Parent pointers, observer lists and doubly-linked lists are all expressible this way | inference must be strongest here, because this is what keeps C3 rare |
| **C3** | **declared weak** — explicit and visible at the declaration site. **Last resort.** | |
| **C4** | ★ **does not exist** — **refuse**, naming the SCC members, the exact field that closes it, and now **three** remedies (borrow the back-edge · declare it weak · give the region an owner, §4.3a). ⚠ **NARROWED 2026-09-04**: the refusal no longer fires on *any* surviving SCC, only on one whose **external in-edges cannot be enumerated** — through FFI, through a raw pointer, or through storage a foreign library owns. | |

★★ **Since 2026-09-04 this is the ONLY refusal class in the memory model**, every other having become TD enforcement (§4.2a). It survives because **a non-tracing mechanism cannot reclaim a cycle** — TD included — so acyclicity is the one property no runtime record can rescue.

⚠ **And it is STRUCTURAL, not epistemic**, which is what makes it compatible with "failure to prove never rejects." It never says *"your program may be fine and we could not prove it."* It says: **this type graph admits a shape nothing short of a tracing collector can reclaim, and here are the two edits that remove it** — decided on the **type** graph, before any value exists, so it is reproducible, explainable, and fixable at the declaration site. → `D-DSSHIR-CYCLE-TYPE-GRAPH-SCC` (which owns the decision this property follows from).

### 4.3a ★★ The cyclic region — an SCC reclaimed as ONE unit, with a declared owner

**Operator ruling 2026-09-04.** C1 says a region freed as a unit makes cycles inside it free, and its own note admits membership *"must be inferable, not only declared."* **This is the declared half.** An owner names the region; the compiler checks the claim; the SCC becomes a **reclamation unit** instead of a refusal. Language surface and spelling are [`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §3.1f.

★ **The mechanism, and why it reclaims a cycle without tracing.** The members of an SCC can never drive each other's counts to zero — that is the whole problem. But **the SCC as a unit can**: count only the edges that *cross into* the region from outside, ignore every edge *inside* it, and free the entire unit when the external count reaches zero. External in-degree can reach zero even though no member's in-degree ever does.

⇒ no heap walk, no runtime type maps, no mark phase, no deferral — an increment when a reference crosses in, a decrement when one crosses out, and destruction at a named program point. **The five not-a-collector properties of §4.2a all still hold.**

⚠⚠ **THE SHARP EDGE, and it is the finding that decides whether this is implementable: "is this edge internal?" is an INSTANCE question, not a TYPE question.** Two independent trees of the same parent-pointered type are two separate regions, and an edge from one into the other is **external** even though both ends have SCC-member types. The type-graph SCC (§4.3) says which types *can* form a region; it cannot say which objects *did*. ⇒ **objects carry a region identity**, and an edge is internal iff both ends carry the same one.

That is a real, non-zero cost and it must be stated rather than discovered: **one region tag per object in a cyclic region.** It is a small constant, it is *not* a shadow metadata system, and objects outside any cyclic region carry nothing — but it is the price of admitting the cycle instead of refusing it, and it belongs in the tier artifact (§4.5) where the trade is visible.

★ **DOCUMENTED prior art, not re-derived here: Project Verona's region model** — objects live in regions with an entry point, cycles inside a region are unremarkable, and the region is reclaimed when its entry dies. Per the provenance rule this is a labelled suspect until probed; what it establishes today is that **region-as-reclamation-unit is a published design rather than an invention of this plan**, which is the relevant fact when deciding whether to build it.

**The check is the whole thing, and it must be TOTAL.** A declared owner is a claim that **no reference to any member of the SCC outlives the owner**. Verification has exactly three outcomes:

| the analysis shows | result |
|---|---|
| no member escapes the owner's extent | ✅ **C1 proper** — static, zero runtime cost, the region dies with its owner |
| members escape, and every external in-edge is enumerable | ✅ the region carries an **external count** — the residual, per region, deterministic |
| an external in-edge cannot be enumerated (FFI, raw pointer, foreign storage) | ⛔ **refuse** — C4, narrowed to exactly this |

⚠⚠ **The declaration is never BELIEVED — it is checked, or it is refused.** An owner the analysis cannot verify must be **rejected, not trusted**: a declaration taken on faith where inference is weak is `@manual` wearing a checkmark, and it produces a use-after-free instead of a leak. **That is the single constraint this whole feature stands on.**

⚠ **The cost that must be written down: reclamation granularity coarsens to the unit.** A member that could have died early lives until its whole region dies. That is a **precision** loss, never a soundness one, and it is exactly the trade C1 always made — now it is made deliberately, at a named declaration, and reported per region in the artifact (§4.5) so nobody discovers it in a profiler.

→ `D-DSSHIR-CYCLIC-REGION-RECLAIMED-AS-A-UNIT`.

★ **Weak is checked, not trusted** — this is what separates it from Swift and Rust, and it reuses a rule this repo already enforces elsewhere:

- A `weak` declaration is **verified to actually break an SCC**. One that breaks nothing is **inert config and is refused** — precisely the bidirectional rule the `runtimeLibraries` table uses (**MEASURED**: *"ADD a row nothing names and validate() refuses it as inert config"*).
- An SCC that **remains** after all declared weaks **and all declared region owners** (§4.3a) is refused, naming what is left.
- ★ **A declared region owner obeys the SAME bidirectional rule as `weak`**: one that owns no SCC is **inert config and is refused**. The rule is not per-feature; it is what this repo does to every declaration that claims to change an analysis.
- ⇒ "the programmer got it wrong" is a **compile error, not a leak.** That is the entire criticism of ARC, answered.

★ **Why a cycle collector is rejected on a ground that cannot be argued around.** It is a GC by another name, and it is unavailable freestanding — both true, and both survivable objections. The one that settles it: a trial-deletion collector must **traverse the heap**, which requires **runtime type maps** (a whole shadow metadata system), and it makes reclamation timing **non-deterministic**. It does not merely *add* a runtime service — it **takes away** the determinism C0/C1/C2 earned. At C0–C3, destruction happens at a known program point. → `D-DSSHIR-NO-CYCLE-COLLECTOR`.

★ **Freestanding meets this by construction:** C0/C1/C2/C3 need **no runtime service whatsoever** — the analysis is compile-time and the emitted code is arena frees and direct destruction. Drivers and boot images ([`plan-28`](./28-driver-builder-plan.md)) are expressible.

★ **The honesty clause — the boundary is stated so nobody overclaims it.** The guarantee covers **compiler-owned edges only**. A cycle formed through **FFI**, through a **raw pointer**, or through memory a **foreign library owns** is not in the owning-edge type graph and is **not covered**. That is correct — reclamation does not track those edges — but it must be written down, because DSS is an FFI-heavy compiler and *"Axis cannot leak"* will otherwise be repeated without its qualifier. **The FFI boundary is where the proof ends**, and the diagnostic vocabulary must say so when a type reaches it. → `D-DSSHIR-RECLAMATION-FFI-BOUNDARY`.

### 4.4 ★ The agnosticism test — c-subset must be a provable no-op

**The hard constraint, and the reason this tier is at 09.5 rather than inside plan 24.**

c-subset declares **no** automatic reclamation, and the tier **must be a provable no-op for it**. C23 has no ownership model — `malloc`/`free` are ordinary library calls with no compiler-tracked ownership, and C23 6.2.4 storage duration says nothing a reclamation pass may exploit.

**The pin: every C example emits BYTE-IDENTICAL code with the tier present and absent.** If that pin cannot be made green, the tier is in the wrong place. No `if (lang == "axis")` anywhere in `src/hir` or `src/dss-hir`. → `D-DSSHIR-CSUBSET-BYTE-IDENTICAL-NOOP`.

**The split, matching what this project has converged on everywhere else:** the **language config** supplies only the **vocabulary** — which constructs create owners, which create borrows, which create shared aliases, which types are recursive, and which lattice tiers this language permits. The **shared tier** owns realization. The **engine intersects**. Identical in shape to `entryVerbs` (**MEASURED**: *"the accepted entry set is an intersection, and this file owns only half of it"*).

### 4.5 Visibility — what stops the hybrid degrading into "refcount everything"

Mechanical, not aspirational. A hybrid whose fallback is invisible becomes T4-everywhere within a year.

- The per-value **tier classification is an emitted artifact** — queryable, stable, diffable — **not log output**.
- It is **assertable in tests**: a corpus example may pin *"this function allocates at T0/T1 only."* A hot loop sliding T1 → T4 or T1 → TD is a **performance regression that reds a test**, not something visible to whoever looks.
- A whole-program **summary per build**: counts per tier, and every site that fell to T4 **or to TD** **with the reason inference failed**.
- ★★ **This section is what carries the 2026-09-04 reversal.** Once an unprovable residual is *enforced* rather than *refused*, the compile error that used to make the frontier impossible to ignore is gone — so the artifact is the **only** thing standing between "enforce where unproven" and TD-everywhere. It was a good idea under the old design; **under this one it is the mechanism the design rests on**, and it must land with the tier rather than after it.
- ★ **Red-on-disable**: weaken one inference rule *in config* → specific sites drop a tier → the pinned example fails. **A config edit, recompiling nothing** — the same lever `cSymbolDecoration` demonstrated (**MEASURED**).

> "No silent performance cliffs" means **the cliff has a test that fails**, not a report someone may read. → `D-DSSHIR-TIER-CLASSIFICATION-ARTIFACT`.

### 4.6 ⚠ The named risk: cross-module inference

**Full cross-module ownership/lifetime inference without annotations is the unsolved part** — it is *why* Rust has lifetime syntax at all. This is the plan's main technical risk and it is not retrofittable.

**Mitigation, designed in from the start:** module **boundaries carry an inferred-and-serialized ownership signature** — *computed, not authored*, but **persisted and version-checked**. Inference stays **intra-module**; the boundary is a **stable declared contract**.

Without it there are only two outcomes, both bad: inference degrades at every module edge (everything falls to T4), or builds become whole-program. **Decide this before T1/T2 are implemented.** → `D-DSSHIR-MODULE-OWNERSHIP-SIGNATURE`.

### 4.7 The refusal diagnostics are the load-bearing part

Because the design gives up total (i), **the refusals are the product**. Each must name the remedy, not merely the fault:

| Refusal | Must name |
|---|---|
| owning SCC with no mechanism | the SCC members, the **exact field that closes it**, and both remedies (borrow the back-edge / declare it weak) |
| inert `weak` | the declaration, and that it breaks no SCC |
| residual below T4 in a lattice **without TD** | the site, **why inference failed**, and **which storage provider is missing** (§4.2a) — ⚠ in a lattice **with** TD this is not a refusal at all: it is a materialization, reported in the artifact (§4.5), never a diagnostic |
| type reaching the FFI boundary | that the proof ends there (§4.3 honesty clause) |

### 4.8 ⛔ `@manual` is DELETED — the section is retired, and the argument recorded

**Operator ruling 2026-09-04 ([`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §2.3a).** This section defined `@manual`: an annotation on classes, functions and bare blocks that **suspended tiers T0–T4** and handed reclamation to the programmer, with `free(x)` modelled as a consuming move so that use-after-free and double-free became the same diagnostic as use-after-move.

**It is removed from the design entirely** — no `@manual`, no `@unmanaged`, no `free`, no `delete`, no per-object opt-out of the model under any spelling. The compiler is responsible for memory **in all cases**.

★ **Retired on its merits, not by decree — because the case it existed for does not need it.** The motivating example was always *a DMA buffer whose lifetime the hardware owns*. Read carefully, that is not a request for manual memory management: it is a **semantic fact about the object** — its storage is owned by an external agent, so the compiler must not reclaim it and must not assume it can. That fact belongs in the **description**, where the analysis can act on it, and this tier already has the boundary for it: §4.3's honesty clause, the FFI edge. ⇒ **the un-inferable case is answered by telling the compiler the truth about the object, never by switching the compiler off for it.**

⚠ **Three consequences, so nothing dangles:**

- **`free`-as-a-consuming-move is retired with it.** The insight was elegant and has nothing left to apply to: with no programmer-callable `free`, use-after-free is not a diagnostic this tier can produce, because the construct that produces it does not exist. ⛔ `D-DSSHIR-FREE-IS-A-CONSUMING-MOVE` is **retired** (§9). ★ **The move machinery is untouched** — T1 still consumes on move, and that is exactly what makes the cross-thread transfer in §4.2a checkable.
- **The `@manual` vs `@kernel` naming analysis is moot** as a decision and stands as a **naming precedent**: *kernel* collides three ways in this repo (**MEASURED 2026-08-12** — [`plan-17`](./17-shader-gpu-plan%20-%20tbd.md) for GPU compute kernels, [`plan-28`](./28-driver-builder-plan.md) for OS kernels and for boot payload kernels). §0.1's second collision item is therefore **closed**: there is no annotation left to name.
- **Freestanding is unaffected, and always was.** A driver never needed `@manual` — T0–T3 are compile-time and work in a kernel. The ⚠ note that used to say so is now simply true without a caveat, and [`plan-28`](./28-driver-builder-plan.md) is updated in the same change.

## 5. Platform absorption — how a service lowers

Each service declares a **vehicle set** per target, following the rule this repo already enforces (**MEASURED**, [`plan-27`](./27-gui-plan.md) §16.3): the **enumerator arrives with its engine arm**; the target/format declares *which vehicles it can realize*; the **contract and state machine are engine-only, never data**.

★ **A service is only in DSS-HIR if it absorbs a real discrepancy.** Renaming a uniform API is not absorption — it is a wrapper, and wrappers belong in a library, not in a compiler tier. `workers` (§3) is the reference case; anything that cannot state its discrepancy as concretely does not earn a slot. → `D-DSSHIR-SERVICE-MUST-ABSORB-A-DISCREPANCY`.

★★ **The runtime is AUTHORED IN HIR SOURCE, therefore compiled by us.** Because DSS-HIR lowers into HIR and HIR is the C/C++-expressible floor (§2.1), the DSS Native Runtime is itself expressible in HIR — and **operator ruling 2026-09-04** ([`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §3.9) makes that mandatory: **100% of the runtime is written in our own HIR**, not in C and not in anything the project already ships as a source language. This preserves [`plan-21`](./21-runtime-reserved-plan%20-%20tbd.md) §3's hermetic invariant and [`ZZ-final-goal`](./ZZ-final-goal.md) §2's property 3 **without a carve-out and without a foreign front end in the runtime's own build**. ⚠ *This sentence previously read "written in DSS Axis (or C)"; the ruling removes the "(or C)".*

⚠⚠ **The timing is part of the ruling and it is NOT now.** The migration happens **when C++ is fully ready** — HIR's ceiling *is* C/C++ expressibility, so the HIR surface rich enough to carry a runtime is precisely the one compiling C++ proves out. Migrating earlier means discovering the missing HIR one runtime feature at a time, underneath everything else. Until then any C under the runtime is a **stated interim, never the design**. ★ And it makes §8 Q1 (`.dsshir` is already plain HIR's text format) a **prerequisite** rather than an open question: once HIR text is authored, reviewed and diffed as real source it must be **human-writable, not merely round-trippable** — a requirement HR7's emit-and-reparse format was never designed for. Settle it while zero HIR source files exist. → [`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) `D-AXIS-RUNTIME-AUTHORED-IN-HIR` — ⚠ **deliberately NOT a twin anchor here**: the authoring language of the runtime is a language/project ruling, and this tier consumes it. Minting a second id for one ruling is how a fact acquires two owners.

## 6. Architectural locks

1. **The disabled path is complete, never degraded** (§2.3). No engine code may assume a DSS-HIR node exists.
2. **HIR keeps its own async/exception/effect attribute families** — a foreign runtime model lowers through plain HIR ([`plan-24`](./24-dss-axis-language-reserved-plan%20-%20tbd.md) §4.2, preserved).
3. **The two facets stay independently switchable** (§2.4) — `memory` without `runtime`, and vice versa.
4. **No T5 and no cycle collector, and their absence is tested** (§4.2, §4.3).
5. **c-subset stays byte-identical** with the tier present (§4.4) — the agnosticism test.
6. **Language config supplies vocabulary; the tier owns realization** — no `if (lang == …)` in `src/hir` or `src/dss-hir`.
7. **Module ownership signatures are inferred-and-serialized, never authored** (§4.6).
8. **A service must absorb a named discrepancy** (§5), or it is a library.
9. **Reclamation is deterministic** — destruction at a known program point, at **every** tier that exists, TD included.
10. ★ **TD never becomes a collector, and the test is mechanical** (§4.2a): no traversal, no deferral, no background thread, no safepoint, no barrier. ⚠ If an implementation of TD finds itself wanting the reserved `GcRoot` / `GcSafepoint` / `GcBarrier` slots (§8 Q7), **that want is the finding** — it is evidence the tier has drifted toward the thing this plan renounces, and it is a design review, not a ticket.
11. ★ **The tier-classification artifact (§4.5) ships WITH the mechanism it reports, never after it.** Under the 2026-09-04 reversal it is the only thing that makes an unprovable residual visible; a tier that enforces silently and reports later has already spent the year in which TD spread.
